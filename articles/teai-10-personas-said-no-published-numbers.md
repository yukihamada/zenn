## 要約

- [teai.io](https://teai.io)(自作のLLMゲートウェイ)と KOE(声クローン)を、競合サービスと徹底比較して、10人のペルソナに厳しく判定してもらった
- **10人中10人が「今は見送り」**。理由は「速い・380+と書いてあるだけで、契約前に確かめられる数字がない」
- その日のうちに、認証なしの公開API `/api/v1/stats/public`・TTFT実測・出金UIを実装して本番に出し、LPから「<100ms」の文言を削った
- 出てきた数字: モデル394・TTFT中央値1.7s・MCP有料呼出**22回**・作者への還元累計**¥32**・外部作者**0人**
- 小さい。でも、非公開のまま「80%還元」と書き続けるより、22回と書いて増やす方がまっすぐだと判断した

## なぜやったか

前回の記事(「[Claude Codeの従量課金が高すぎて、自分でLLMゲートウェイを作った話](https://zenn.dev/yukibjj/articles/teai-claude-code-too-expensive-sente)」)には少し反応があった。機能紹介よりも「困ったから作った」という話の方が届く、というのは実感としてあった。

じゃあ、次に困っているのは何か。正直に言うと「**誰も使っていない**」ことだった。

自分で書いた比較表は、自分に都合よくできている。そこで、立場の違う10人のペルソナ(SaaSのCTO、大手の情シス調達、MCPツール作者、VTuber、ALS患者の家族、VC、音楽プロデューサー、米国のMLエンジニア、ポッドキャスター、AI倫理研究者)を立てて、「あなたなら買うか・使うか」を辛口で判定させた。マルチエージェントで、それぞれ独立に。

| 情シス調達 | ✕ | SOC2未取得。稟議が通らない |

| 音楽P | ✕ | 二次利用・派生作品の分配設計がない |

10人が別々の言葉で言っていたことは、突き詰めると1つだった。

> **自称値しかない。契約前に確かめられる数字がない。**

## その日にやったこと

反省文を書く前に、実装した。

### 1. 公開KPI API(認証なし・60秒キャッシュ)

```bash
curl -s https://teai.io/api/v1/stats/public | jq '{models, mcp, developer_payout_jpy_equiv}'
```

```json
{
  "models": { "total": 394, "providers": 11 },
  "mcp": {
    "builtin_services": 16, "builtin_tools": 81,
    "mcp_services_active": 5, "mcp_tools": 5, "koe_voices": 4,
    "paid_calls_total": 22, "developer_credits_total": 197, "developers_paid": 2
  },
  "developer_payout_jpy_equiv": 32
}
```

モデル数・MCPツール数・声の数・累計有料呼出・累計還元クレジット(と円換算)。ユーザー数やメールなど個人情報は含めない。

Rust(axum)側は `mcp_services` / `mcp_earnings` テーブルの集計を1本追加しただけ。ただ、初回デプロイで `mcp_services_active: 0` になって焦った。存在しない `status='active'` で絞っていたのが原因で、実際の値は `live`(第三者MCP)と `internal`(声)だった。自分のコードの status 値すら把握していなかった、という話。

### 2. TTFTを測る

既存のレイテンシ計測は「完了までの時間(E2E)」だけだった。対話UIで体感するのは「最初の1文字まで(TTFT)」なので、計測プローブをストリーミング化して両方を出すようにした。

```bash
curl -s https://teai.io/api/v1/latency | jq '.measured[] | {model, ttft_median_ms, median_ms}'
```

計測方法(同一プロンプト・逐次実行・30分ごと・空応答は失敗に数える)も同じJSONに入っている。

限界も書く。**各モデル1サンプルの単発値**なので、30分ごとに値が揺れる。この記事を書いている間にも最速TTFTが420ms→600msに動いた。p95が言えるまでサンプルを溜める。

### 3. LPから「<100ms」を削った

「東京サーバーで100ms以下」という文言があった。ゲートウェイのプロキシ部分だけを指していたのだろうが、根拠を辿れなかった。実測するとゲートウェイ応答は0.18s、推論込みのTTFTは最速0.57s。矛盾するので削り、実測APIへのリンクに置き換えた。

LPの数字は静的な「380+」から、APIを叩いて60秒ごとに更新する形に変えた。失敗したら「—」のまま。数字を作らない。

### 4. 出金UIを作った

80%還元の出金APIは前から存在していたが、UIがなかった。しかも既存ページの「出金は収益ページへ」のリンク先が存在しないページだった。フォームを付けた。

### 5. KOE側の矛盾表記を直した

koe.live/earn には「現金での分配は次の段階で準備中」とあった。一方teai側には出金APIとStripe Connectが実装済み。経路で違う、というのが実態だったので、そう書き直した。

- teai.io経由(MCPで誰かがあなたの声で喋る): 80%記帳 → 出金申請 → 振込。**動いている**
- koe.live直の利用: コミュニティ通貨(ASH)のみ。現金化は次段階

## 出てきた数字(2026-09-10)

| 項目 | 以前の表記 | 実測 |
|---|---|---|
| モデル数 | 380+ | 394(11プロバイダ) |
| レイテンシ | <100ms | GW応答0.18s / TTFT 0.57〜6.7s(中央値1.7s) |
| MCPツール | 「マーケット」 | 86(運営81+第三者5) |
| 有料呼出・累計 | 非公開 | **22** |
| 作者への還元・累計 | 非公開 | **197cr(¥32)・作者2名・外部0** |
| KOE 声 / 再生 | 非公開 | 13 / 33,003 |

有料呼出22回。外部作者ゼロ。還元¥32。

これを「稼げるマーケット」とは呼べない。VCのペルソナが言った通り、投資判断以前の数字だ。

でも、公開してみて思ったのは、**非公開の「80%還元」より、公開の「22回」の方が、次に何をすべきかがはっきりする**ということだった。数字がないと「もっと機能を」になる。数字があると「外部作者を1人」になる。

## ペルソナはどれだけ動いたか(推定)

再評価はまだしていないので推定だが、今回の実装で✕→△に動きそうなのはCTO・米国ML・ポッドキャスターの3人。残りは実装ではなく、SOC2・TTSのブラインド比較・権利設計・非技術者向けUXが必要で、これは次の宿題。
